## RubiGUI Word版 v2.1 — 2026-08-10

対象: `RubiGUI_word_v2.1/RubiGUI_V2.1.py` / `RubiGUI_word_v2.1/Module1.bas`

### ⚠ 移行時に必要な作業

**Wordマクロ（Module1.bas）の入れ替えが必須。**

マクロ名と引数が変わっている。

| | マクロ名 | 引数 |
|---|---|---|
| v2.0 | `InsertFuriganaFromTSV_SaveToNewFile_Stable` | なし（`ActiveDocument` とデスクトップパスの推測に依存） |
| v2.1 | `InsertFuriganaFromTSV_V21` | 元ファイル / TSV / 出力先 の3パス |

TSVの書式も変わっているため、旧マクロに新しいTSVを渡すと「1行もルビが振られない」という
分かりにくい失敗になる。これを避けるためマクロ名を変更した。名前が変わっていることで
`word.Run` が必ず失敗し、Python側が「Module1.bas を入れ直してください」と案内できる。

手順:

1. Word を起動し `Alt + F11` でVBAエディタを開く
2. `Normal` → 標準モジュール の古い `Module1` を右クリック →「Module1 の解放」→「いいえ」
3. `Normal` を右クリック →「ファイルのインポート」→ `RubiGUI_word_v2.1/Module1.bas`

### 追加

- **ルビを振る範囲を選べるようになった**（`初回のみ` / `すべての出現箇所`）。
  既定は `初回のみ`。設定は `ruby_settings.json` に保存され次回起動時も引き継がれる。
- **ルビの大きさ（親文字の％）とルビの高さ（pt）をGUIから設定できるようになった。**
  v2.0 はマクロ内で `FontSize:=6` に固定されており、大きな文字にルビを振ると
  極端に小さくなっていた。v2.1 は出現箇所ごとに親文字サイズから計算する。
- `ruby_settings.json`（新規）と `requirements.txt`（新規）を同梱。
- マクロが処理件数を `<TSV>.result` に書き出すようにし、完了メッセージで
  「ルビ N 件を付与しました」と表示するようにした。

### 修正

- **同じ語句が複数回出てきても最初の1箇所にしかルビが振られなかった。**
  `Module1.bas` のループが `Set rng = docNew.Range(rng.End, ...)` で Range を
  作り直す一方、`.Find` の条件を再設定していなかったため、2回目以降の
  `Find.Execute` が成立していなかった。

  v2.1 は検索のたびに条件を設定し直したうえで、処理を**2段階**に分けた。
  1. **位置決め**: 文書を一切変更せずに、全語句の付与位置を洗い出す。
  2. **付与**: 決めた位置へ、文書の**末尾から前へ**向かって `PhoneticGuide` を適用。

  `PhoneticGuide` は対象文字列をルビ付きの構造へ置き換えるため、実行のたびに
  それ以降の文字位置がずれる。位置決めと付与を混ぜると「次にどこを探すか」が
  分からなくなるが、先に全位置を確定して後ろから処理すれば、未処理側（前方）の
  位置は一切ずれない。
- **`.MatchWholeWord = True` による取りこぼし。**
  日本語は分かち書きしないためこの指定は不適切。`False` に変更した。
  あわせて日本語版Wordの「あいまい検索」（`MatchFuzzy`）も明示的に切った。
- **語句の重なり**（「日本」と「日本人」）。
  Pythonが**表層形の長い順**にTSVを出力し、マクロが上から処理する。
  位置決めの段階で確定済みの文字位置を `occupied` に記録し、重なる候補は
  採用しない。これにより長い語句が優先され、その内側へ短い語句のルビが
  二重に載ることがない。
  ※当初は「既にルビが付いている箇所か」を `Range.Fields` で判定していたが、
  Wordのふりがなの内部表現はバージョンによって EQ フィールドだったり
  `w:ruby` だったりするため、この判定では取りこぼす。文字位置で管理する
  方式に変更し、Wordの内部表現に依存しないようにした。
- **「初回のみ」モードで、最初のヒットが他の語句のルビと重なっていると
  その語句を諦めていた。** 重なりで見送った場合は次の出現箇所を探すようにした。
- **一時ファイル `_temp_〇〇.docx` の消し残り。**
  v2.0 のマクロは `fso.GetParentFolderName(doc.Path)` を使っており、これは
  「文書のあるフォルダ」ではなく**そのさらに親フォルダ**を返していた。
  一方 Python 側の後片付けは `%TEMP%` を見ており、そもそも噛み合っていなかった。
  v2.1 は出力フォルダの中に作業用コピー `~rubigui_〇〇（ルビ）.docx` を作り、
  それだけを編集して、最後まで成功したときに正式な出力名へ差し替える。
  元ファイルには一切書き込まない。
- **デスクトップパスの不一致。**
  Python はレジストリ `User Shell Folders` から、マクロは
  `WScript.Shell.SpecialFolders("Desktop")` から取得しており、OneDriveで
  デスクトップがリダイレクトされている環境で食い違い得た。
  v2.1 はパスを3つとも引数で渡すため、この不一致が発生しない。
- **TSVを cp932 から UTF-8（BOM付き）へ変更。**
  v2.0 はVBAの `Open ... For Input` がANSI固定だったため、cp932で表現できない
  語句（㈱・髙・𠮟 などの機種依存文字を含むもの）をPython側で除外していた。
  マクロを `ADODB.Stream` でのUTF-8読み込みに変更し、この制限を撤廃した。

  TSVの書式（UTF-8 BOM付き・LF改行）:

  ```
  #RUBIGUI    2.1
  #mode       first
  #ratio      50
  #offset     0
  #DATA
  日本人      にほんじん
  名古屋      なごや
  ```

  `#DATA` は設定行の終端マーカー。これ以降は `#` で始まっていても語句として扱う。
  語句は表層形の長い順。
- **1文字の語句を `override.json` に登録しても効かなかった。**
  `extract_terms` が文字数チェックを辞書判定より先に行っていた。順序を入れ替えた。
- **文字数の多い文書で語句抽出が例外になっていた。**
  SudachiPy の入力上限（49149バイト）に引っかかっていた。PPT版と同じ
  `_split_for_tokenizer` / `tokenize_all` を移植し、改行や句読点で分割する。
- **段落をまたいだ実在しない語句が一覧に出ていた。**
  `w:t` を全部 `""` で連結していたため「会社」＋「員研修」→「会社員研修」の
  ような語が生まれていた。段落（`w:p`）単位で改行を挟むようにした。
  あわせて、マクロの検索が届かないテキストボックス（`w:txbxContent`）内の
  文字を解析対象から除外した。
- **一括処理のあと、前のファイルの語句が画面に残っていた。**
  その状態で「ルビ付きWord出力」を押すと別ファイルの読みが使われていた。
  PPT版と同じ `_clear_current_file()` を追加。
- **「一括処理(確認あり)」と「▶ 次へ」が別々のファイル一覧を見ていた。**
  「次へ」は `self.files`、確認処理は `self.docx_files` を参照しており、
  `select_folder` を通らないと `AttributeError` になっていた。
  `self.docx_files` に統一し、確認画面を経ていないときは動かないガード
  （`review_ready`）を追加した。
- **設定ファイルをカレントディレクトリから探していた。**
  ショートカットの作業フォルダが空の場合などに `override.json` が
  1件も読み込まれず、「辞書編集を開いても一覧が空」になっていた。
  `override.json` / `sudachi.json` / `ruby_settings.json` / ログの各パスを
  アプリ本体と同じフォルダ基準に変更した。
- 語句一覧の再読み込み前に確認する `_confirm_discard_edits()` を追加
  （手で直した読みが黙って消えるのを防ぐ）。
- フォルダ内のファイル列挙を `glob.glob` から `Path.glob` へ変更。
  `glob.glob` はフォルダ名の `[ ]` をワイルドカードとして解釈するため、
  「資料[2024]」のような名前のフォルダで0件になっていた。
- 壊れた `.docx` を開いたときに例外で落ちず、エラー内容を表示するようにした。
- マクロのエラー通知を `MsgBox` から `Err.Raise` に変更。
  `MsgBox` はクリックされるまで戻らないため、一括処理が途中で止まっていた。
- **起動中のWordを乗っ取って非表示にし、最後に終了させていた。**（v2.0 からの積み残し）
  `Dispatch("Word.Application")` は起動中のWordにアタッチするため、ユーザーが
  別の文書を編集中に実行すると、そのウィンドウが消えて処理後に `Quit()` で
  巻き添えになっていた。PPT版の `get_powerpoint()` と同じ考え方の `get_word()` を
  追加し、`GetActiveObject` で既存インスタンスを見つけた場合は `Visible` も
  `Quit()` も触らないようにした。
- **マクロ側の正当なエラーが「Module1.bas を入れ直してください」に化けていた。**
  VBA の `Err.Raise ..., "RubiGUI", "TSVファイルが見つかりません…"` のうち
  `"RubiGUI"` は `com_error.excepinfo[1]`（ソース名）に入るのに、説明文
  （`excepinfo[2]`）の側で判定していたため常に汎用メッセージへ落ちていた。
  ソース名で判定するよう修正。
- **`#` で始まる語句がTSVの設定行と誤認されて捨てられていた。**
  設定の終わりを示す `#DATA` 行を追加し、それ以降は `#` で始まっていても
  語句として読むようにした。
- **マクロが失敗すると `.result` が消えずに残っていた。** 成否にかかわらず
  読んで消すようにし、`error` 行も解釈するようにした。
- **ルビのフォントに欧文フォント名が優先されていた。** ルビは必ず仮名なので
  `Font.NameFarEast` を優先する。本文が「欧文=Calibri／日本語=游ゴシック」の
  ような設定のとき、ルビだけ別書体になっていた。
- 読み込めないファイルを飛ばす処理が再帰だったため、読めない `.docx` が
  大量にあるフォルダで `RecursionError` になり得た。ループに変更（PPT版も同じ）。
- **`override.json` に「読み＝語句」のエントリがあると無意味なルビが振られていた。**
  辞書判定を文字数チェックより前に出した副作用で、`{"ひつまぶし": "ひつまぶし"}`
  のような登録がすべての除外ルールを素通りしていた。読みが語句と同一の場合は
  辞書登録でも対象外にした（PPT版も同じ）。
- **Wordがビジーなだけのエラーまで「マクロを入れ直せ」と案内していた。**
  起動中のWordにアタッチするようになった副作用で、Word側にダイアログが
  開いていると `RPC_E_CALL_REJECTED` で失敗する。この系統のエラーコードは
  「Wordが応答できる状態ではありません」という案内に分けた。
- **`Find.MatchByte` を明示していなかった。** 日本語版Wordのこの設定は
  ユーザーごとに残るため、環境によって「ＡＩ」を探して「AI」に当たるなど
  半角と全角を取り違えていた。`True` を明示。
- **マクロが途中で失敗すると、ルビの無いコピーが完成品の名前で出力フォルダに
  残っていた。** 出力フォルダ内の作業用コピー `~rubigui_〇〇（ルビ）.docx` を
  編集し、最後まで成功したときだけ正式名へ差し替えるようにした。
  失敗時は作業用コピーを削除する（前回成功した出力はそのまま残す）。
  ただし**ルビ付与が終わった後の改名だけが失敗した場合は削除しない** —
  そこにしか完成品が無いため、消すと成果物そのものが失われる。この場合は
  作業用コピーの場所をエラーメッセージに載せて手動で改名できるようにした。
  作業用コピーの名前には日時を入れて実行ごとに一意にしてある。固定名だと、
  こうして意図的に残した完成品を次回の実行が上書き・削除してしまうため。
  代わりに自己修復（次回の上書き）が効かなくなるので、同じ出力名に対応する
  24時間より古い残骸は実行のたびに自動で掃除する。
  あわせて、ファイル列挙が `~` で始まるファイル（Officeのロックファイルと、
  この作業用コピー）を対象外にするようにした（両版）。
- **1つの語句が何千回も出てくる文書でWordが「応答なし」に見えていた。**
  2段階化で `DoEvents` が語句単位に後退していたため、ヒット単位でも
  息継ぎするようにした。
- **マクロが `.result` に書いた `error` 行を誰も見ていなかった。**
  例外がPythonまで届かなかった場合に「保存しました」と表示され得たので、
  `error` が立っていればエラーとして扱うようにした。

### 削除・整理

- `cleanup_temp_file()` / `save_ruby_word()` / `wait_for_ruby_file()` を削除。
  `save_ruby_word()` は出力先から同じ出力先へ `replace` していただけの死にコード。
  マクロが同期的に保存するようになったのでポーリングも不要になった。
- `run_vba_macro()` から `doc.Path` 取得・迷子ドキュメント走査を削除。
  Python は文書を開かなくなった。
- 未使用だった `on_drop` / `select_file_for_review` / `batch_process_from_folder` /
  `apply_ruby` / `process_single_file` を削除。

### 画面

- 辞書編集画面を作り直した。→ 「共通」の項を参照。
- 右カラムに「ルビ設定」「ルビを振る範囲」を追加。ウィンドウ既定サイズを
  800x600 から 860x640 に拡大。

## RubiGUI PowerPoint版 v1.1 — 2026-08-10

対象: `RubiGUI_ppt_v1.1/RubiGUI_PPT_V1.1.py`

### ⚠ 既定の挙動が変わる

v1.0 は常に**すべての出現箇所**にルビを振っていた。
v1.1 は Word版と既定を揃えるため、既定が**初回のみ（資料内で最初の1箇所）**になる。
v1.0 と同じ動作にしたい場合は「ルビを振る範囲」で「すべての出現箇所」を選ぶ。

### 追加

- **ルビを振る範囲を選べるようになった**（`初回のみ` / `すべての出現箇所`）。
  - 「初回のみ」の判定単位は**ファイル単位**。「最初」はスライド順 → 図形順。
  - 消費済みの登録は**ルビの配置に成功してから**行う。配置に失敗して
    ロールバックされた語句まで消費済みにすると、その語句が資料内の
    どこにもルビなしになってしまうため。
  - `build_ruby_blocks` は `(ブロック一覧, 候補の表層形)` を返すようになり、
    ブロックは `(開始位置, 文字数, ルビ, 表層形)` の4要素に変更。
    `place_ruby_boxes` は `(作成した図形, 実際に配置できた表層形)` を返す。

### 修正

- **設定ファイルをカレントディレクトリから探していた。**
  Word版と同じく、`override.json` / `sudachi.json` / `ruby_settings.json` /
  ログの各パスをアプリ本体と同じフォルダ基準に変更した。
- `override.json` が辞書形式でない場合に落ちないようにした。
- **処理が途中で失敗すると、ルビの無いコピーが完成品の名前で出力フォルダに
  残っていた。** v1.0 は正式な出力名へ直接コピーしてから、その場で編集して
  いた。Word版と同じく作業用コピー `~rubigui_〇〇（ルビ）.pptx` を編集し、
  保存まで成功したときだけ正式名へ差し替えるようにした。失敗時は作業用
  コピーを削除する（改名だけ失敗した場合は、成果物が失われないよう残す）。
- 読みが語句とまったく同じ辞書エントリを対象外にした（Word版と同じ）。
- ファイル列挙が `~` で始まるファイル（ロックファイルと作業用コピー）を
  対象外にするようにした。
- 読み込めないファイルを飛ばす処理が再帰だったのをループに変更した。

### 画面

- 辞書編集画面を作り直した。→ 「共通」の項を参照。
- 右カラムに「ルビを振る範囲」を追加。

## 実機テストで見つかった不具合の修正 — 2026-08-12

### Word v2.1：ルビを1件でも振ろうとすると Word がクラッシュしていた

- **症状**: 「ルビ付きWord出力」を実行すると、数秒後に
  「リモート プロシージャ コールに失敗しました（0x800706BE）」で失敗する。
  イベントログには `WINWORD.EXE` が `wwlib.dll` でアクセス違反
  （0xC0000005）を起こした記録が残る。VBAのエラーではないので ErrHandler も
  動かず、`.result` も書かれず、作業用コピーだけが残る。
- **原因**: `Documents.Open` に `Visible:=False` を指定していたため、
  **ウィンドウが表示されていない文書に対して `PhoneticGuide` を呼んでいた**。
  この状態では `Application.ActiveWindow` すら「文書が開かれていないため
  使用できません」になり、Word が内部で落ちる。
  v2.0 は既定（`Visible:=True`）で開いていたため発生していなかった。
- **切り分け**: TSVの語句を0件にするとマクロは完走し、1件にすると必ず
  クラッシュした。同じ引数（Alignment=0 / Raise=0 / FontSize / FontName）で
  Python から外部プロセス経由で `PhoneticGuide` を呼ぶと44件すべて成功する
  ため、原因はパラメータではなく文書のウィンドウ状態だと確定した。
- **修正**: `Visible:=True` で開き、`docNew.Activate` で明示的にアクティブに
  してからルビを振る。Word のアプリケーション自体は Python 側が非表示に
  しているので、画面には出てこない。
  **この修正には Module1.bas の再インポートが必要。**
- あわせて `RPC_S_CALL_FAILED (0x800706BE)` を Python 側の「接続が切れた」
  分類に追加した。従来はこの系統も「マクロを入れ直してください」という
  見当違いの案内になっていた。

### Word v2.1：処理は成功しているのに作業用コピーが残る

- **症状**: 一括処理のあと、出力フォルダに `~rubigui_日時_〇〇（ルビ）.docx` が
  残る。ログ上はマクロ成功（`applied=144`）で、正式な出力も正しく作られている。
- **原因**: 作業用コピーの置き場所を**出力フォルダ（OneDriveの同期対象）**に
  していたため、`MoveFile` の直後に同期エンジンが元の名前のファイルを
  復活させることがあった。残ったファイルは元ファイルとバイト単位で同一
  （sha256 一致）、出力ファイルの作成時刻は作業用コピーの作成時刻と一致して
  おり、改名自体は成功していることを確認した。
  これは v2.0 のコメントに残っていた既知の罠（「OneDriveの同期タイミングに
  よっては一度削除したファイルが復活してしまうレース条件」）と同じもので、
  v2.0 は作業ファイルを `%TEMP%` に置くことで回避していた。
- **修正**: 作業用コピーを `%TEMP%`（同期対象外）に作り、出力フォルダへの
  書き込みを最後の上書きコピー1回だけにした。`%TEMP%` が取得できない環境では
  従来どおり出力フォルダへフォールバックする。
  あわせて「削除してから移動」をやめ、上書きコピー1回にした（削除と移動の
  あいだで失敗すると出力が消えたままになる隙間があったため）。
  古い残骸の掃除は `%TEMP%` と出力フォルダの両方を見るので、旧版が出力
  フォルダに残した分も自動で回収される。
  **この修正には Module1.bas の再インポートが必要。**

### 両版：exe のビルド手順を追加した

- `packaging/build_exe.py` で両版の exe をビルドできるようにした
  （`--onefile --noconsole`、出力先は各バージョンのフォルダ）。
- **PyInstaller 標準の sudachipy フックが使わない辞書を同梱してしまう問題**を
  回避するため、`packaging/hooks/hook-sudachipy.py` で上書きした。
  標準フックはインストール済みの `sudachidict_full`（359.8MB）と
  `sudachidict_core`（217.1MB）を無条件に取り込むため、exe が 215MB に
  膨らんでいた。RubiGUI はこれらを使わず、exe と同じフォルダの
  `system_full.dic` を実行時に読む。除外して **17.8MB** になった。
  `--exclude-module` では止められない（フックが `collect_data_files` を
  直接呼んでいるため）。
- `.gitignore` に `*.exe` を追加した（readme には「除外している」と
  書かれていたが実際には入っていなかった）。

### 両版：起動時の黒いコンソール画面を隠した

- GUIアプリなのに、起動するとコマンドプロンプトの黒い画面が一緒に出ていた。
- `hide_console_window()` を追加し、起動直後に隠す。
  **既存のコマンドプロンプトやターミナルから実行された場合は隠さない** —
  そのウィンドウはユーザーのものなので、隠すと作業中の画面ごと消えてしまう。
  `GetConsoleProcessList` が 1 を返す（＝このアプリのためだけに作られた
  コンソール）ときだけ `ShowWindow(SW_HIDE)` する。
- コンソールが無い環境（`pythonw.exe` 起動、`--noconsole` のexe）では
  `sys.stderr` が `None` になるため、`StreamHandler` はそのときだけ足す。
- コンソールを隠すと想定外のエラーが画面に出なくなるので、`__main__` に
  最後の受け皿を追加し、ログへ記録したうえでダイアログで知らせるようにした。
- readme に起動方法（`pythonw.exe` のショートカット、PyInstaller の
  `--noconsole`）を追記した。

### PPT v1.1：元から行間が広いスライドだけ極端に間延びしていた

- **症状**: 行間1.5があらかじめ設定されたスライドだけ、ルビ振り後に
  行間が 2.25 になり、他のスライドと見た目が揃わない。
- **原因**: `adjust_line_spacing` が設定値を**元の行間に掛けて**いた
  （1.5 × 1.5 = 2.25）。
- **修正**: 設定値を「最低限確保する行間」として扱う（`max` を取る）。
  必要なのはルビを置く高さの確保であって、元の行間に比例した上乗せでは
  ないため。元から設定値より広い段落はそのまま変更しない。

## 共通 — 辞書編集画面の作り直し（Word v2.1 / PPT v1.1）

### 変更前の問題

- 一覧とボタンが**上下に積まれ**、一覧に**スクロールバーが無かった**ため、
  登録語句が増えると下の方を確認できなかった。
- ウィンドウサイズが 500x500 固定でリサイズできなかった。
- `self.override_dict` を即時書き換えていたため、× で閉じると
  メモリ上の辞書とファイルの内容が食い違ったままになっていた。

### 変更後

```
┌──────────────────────────┬────────────────┐
│ 語句        読み（五十音順） ▲│ 登録数: 32 件   │
│ 名古屋      なごや          █│ ─ 新規追加 ─    │
│ 愛知県      あいちけん      █│ 語句 [        ] │
│ …                         ▼│ 読み [        ] │
│                             │ [   追加   ]    │
│                             │ [選択した語句を編集]│
│                             │ [選択した語句を削除]│
│                             │                 │
│                             │ [保存して閉じる] │
│                             │ [キャンセル]     │
└──────────────────────────┴────────────────┘
```

- 一覧（左）＋操作パネル（右）の**左右レイアウト**。`grid` で列0のみ伸縮。
- 一覧に**縦スクロールバー**を追加。ウィンドウは**リサイズ可能**（最小 620x360、初期 780x520）。
- 読みの**五十音順**で表示し、**登録件数**を表示。行は縞模様。
- **編集は作業用コピーに対して行う。**「保存して閉じる」を押したときだけ
  `override.json` へ書き込む。「キャンセル」／× は変更を破棄（未保存があれば確認）。
- 既存語句を追加・改名しようとした場合に**上書き確認**を出す。
- 削除時に**確認ダイアログ**を出す（Word版には無かった）。
- 保存失敗（`OSError`）を握りつぶさず通知する。
