# 動作確認用のフィクスチャと照合スクリプト

Word版・PowerPoint版の動作確認を、毎回同じ観点で行うための道具一式。

## なぜあるのか

v2.1 では**表を入れた文書で確認していなかった**ため、「表の中を検索すると
空回りして処理が終わらない」不具合を出荷まで見逃した。手作りの確認用ファイルは
どうしても入れ忘れが起きるので、確認したい要素をスクリプトに列挙して
毎回同じものを生成できるようにしてある。

## 使い方

### 1. フィクスチャを作る

```
python tests/make_fixture_word.py
python tests/make_fixture_ppt.py
```

`tests/fixtures/` に `word_fixture.docx` と `ppt_fixture.pptx` ができる。
Word / PowerPoint をCOMで操作して作るので、実行中は勝手にウィンドウが開く。

### 2. アプリで処理する

生成したフィクスチャをアプリにドロップして「ルビ付きWord出力」
／「ルビ付きPowerPoint出力」を実行する。
出力は `デスクトップ／ルビ振り／出力（ルビ付き）／` に入る。

※ Word版は事前に `RubiGUI_V31.bas` を Normal.dotm へインポートしておくこと。

### 3. 結果を照合する

```
python tests/check_word_output.py "…／出力（ルビ付き）／word_fixture（ルビ）.docx"
python tests/check_ppt_output.py  "…／出力（ルビ付き）／ppt_fixture（ルビ）.pptx"
```

期待どおりなら `すべて期待どおりです。`、食い違えば `★NG:` と終了コード1。
PPT版でタイトルにもルビを振る設定で試した場合は、第2引数に `true` を付ける。

## 仕掛け

場所ごとに「そこにしか出てこない地名」を置いてある。処理後の出力を調べると、
どの場所にルビが付いてどの場所に付かなかったかが地名で判別できる。

| | Word | PowerPoint |
|---|---|---|
| **付くべき** | 通常段落(京都) / 単純な表(大阪) / セル結合の表(名古屋) / 入れ子の表(札幌) / 箇条書き(仙台) / 段組み(広島) / 複数回出る語(神戸) / 全角スペース字下げ(横浜) | 本文プレースホルダ(名古屋・京都) / 縦書きTB(大阪) / 複数行TB(仙台) / 1行TB(広島) / 行間1.5済みTB(神戸) / 自動調整TB(横浜) / 空欄のある本文TB(奈良) |
| **付かないはず** | テキストボックス(福岡) / 図形(熊本) / ワードアート(長崎) / SmartArt(鹿児島) / グラフ(沖縄) / ヘッダー(青森) / フッター(秋田) / 脚注(岩手) / コメント(山形) | 図形(福岡) / 表(熊本) / グループ内(長崎) / SmartArt(鹿児島) / グラフ(沖縄) / ワードアート(青森) / ノート(秋田) / 回転図形(岩手) |
| **参考** | 元からルビのある語(奈良)＝二重ルビにならないか | タイトル(札幌)＝`include_title` の設定どおりか |

「付かないはず」の場所は、いずれも本文(Word: `Document.Content` ／
PPT: テキストボックスとタイトル以外のプレースホルダ)に含まれないため、
そもそも語句一覧にも出てこないのが正しい挙動。

### PPT版で特に見ている不変条件

抽出側の `_xml_is_target` と適用側の `is_target_shape` は別実装で同じ判定を
している。ここがずれると「語句一覧には出るのにルビが振られない語句」が
生まれる。全種類のオブジェクトを1つのファイルに置いてあるので、
この2つの整合性がまとめて検証できる。

## 注意

`check_ppt_output.py` はルビ用シェイプを**タグ (`RUBIGUI_ROLE=RUBY`)** で
見分けている。図形名 (`RUBIGUI_RUBY_*`) で探すと取りこぼす。
名前を付けているのはグループ化する経路だけで、プレースホルダに付けたルビは
（PowerPointの仕様上グループ化できないため）既定名のまま残るため。
